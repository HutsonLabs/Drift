Drift on macOS, iPad and iPhone — Mac vs GNOME targets

Part 1 is the app as built on main (26.10). Part 2 is a proposal. Red markers show where a Mac running Drift Host gets GNOME behaviour today. Blue markers show the proposed changes. Part 2 needs no schema change to start: the kind is just profile.paired_host.is_some().

Today One kind of connection, three GNOME modes

The gallery, title bar and edit sheet only know the connection mode (Headless / Desktop Sharing / Remote Login). Pairing a Mac saves a Headless session profile (drift-core/src/pairing.rs), so a Mac card and a GNOME card look the same, and the Mac's edit sheet shows GNOME wording.

Left: GNOME. Right: Mac. Same key row, same chrome.

1Cards look the same. A Mac shows the Headless glyph and says "Headless session". Only the live thumbnail shows it's a Mac.
2Idle Mac cards can't be told apart. Thumbnails are kept in memory only, so a saved Mac gets the same blue Headless gradient as Fedora Server.
3There are two ways to add a connection. The toolbar has a display icon ("Pair a Mac") and a "+" (GNOME only, though nothing says so). The welcome text only says "Add a GNOME computer".
4The mode picker shows on a Mac. Desktop Sharing and Remote Login are GNOME modes, and the hint text describes GNOME.
5The credential hints are for GNOME. They tell you to run grdctl, but a Mac uses the account you paired with.
6Keyboard and display are worded for GNOME. "⌘ sends Super" and "Mac layout" don't apply to a Mac, and Retina says "Renders GNOME at 2×". The Mac-only features (virtual display, quality ladder, HDR) have no settings here.
7The title bar is the same for both. The capsule shows the mode glyph. It doesn't say Mac or GNOME, Drift Host or RDP.
8Mac-only features are hidden. Menu mirroring (EXT-3) only works for a Mac and quality hints (EXT-4) only show in the stats HUD. Nothing in the UI shows they're there.
9The iPhone key row is the same for both. It uses PC-style "ctrl alt ⌘". A Mac needs ⌃ ⌥ ⇧ ⌘ and shortcuts like ⌘Space and ⌘Tab. GNOME needs Super / Activities.

Proposed Two target kinds: Mac and GNOME

The kind is chosen first and drives the chrome: glyph, detail line, which settings the sheet shows, key row, add flow. The GNOME mode stays a property of GNOME targets only. Kind = paired_host.is_some() today. Make it an explicit HostKind later if a third kind (e.g. a Windows RDP host) shows up.

AFilter by kind. The filter becomes All / Macs / GNOME / Open. It stays one gallery; when there are both kinds, Saved could also split into "Macs" and "GNOME".
BOne add button. "+" asks which kind first and replaces the separate "Pair a Mac" icon. The empty state shows the same two choices.
CGlyph, badge and detail line show the kind. A Mac card says "Drift Host · link · quality". A GNOME card keeps "host · GNOME mode".
DIdle art matches the kind. A saved Mac gets a muted macOS-style tile and GNOME keeps the mode gradients. Thumbnails stay in memory only.
EEach kind gets its own sheet. A Mac drops the mode picker, RDP credentials, grdctl hints, "⌘ sends" and Mac layout. It shows pairing, link path (HOST-14), virtual display (HOST-10), quality (EXT-4), HDR (EXT-5) and menu mirroring (EXT-3).
FThe title bar says what's on the other end. It shows the kind glyph, plus the GNOME mode, or the Mac's live quality step.
GiPad gets a sidebar grouped by kind, with an add item in each group. iPhone keeps the single-column gallery with a kind segment at the top.
HThe iPad menu bar fits the kind. A Mac mirrors its menus (as now). GNOME gets Drift's own Session / Keys menus plus Activities and Show Apps, so the bar isn't empty.
IEach kind gets its own key row. Mac: ⌃ ⌥ ⇧ ⌘ with ⌘Space and ⌘Tab. GNOME: Ctrl Alt ⇧ Super and an Activities key. Pick from the kind in renderKeyRow.
